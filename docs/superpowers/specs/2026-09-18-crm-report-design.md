# CRM 客戶報表工具設計 — report.html

日期：2026-09-18
狀態：已獲使用者口頭同意

## 目標

製作一個**單一 HTML 檔案**（`projects/crm/report.html`），讓使用者在本機瀏覽器開啟後，以拖曳或選檔方式載入 `customer.xlsx`，即時產生業務開發報表：總覽統計、圖表、可篩選明細表，並支援 CSV 匯出與列印 PDF。

## 硬性約束

- **零依賴、完全離線**：不使用 CDN、不引入任何 JS 框架或函式庫，全部原生 Web API。
- **單一檔案**：HTML + CSS + JS 全部內嵌在 `report.html`。
- 支援本機 `file://` 開啟（不需伺服器）。
- UI 使用繁體中文。

## 支援的檔案

- 主格式：`.xlsx`。解析方式：瀏覽器原生 `DecompressionStream('deflate-raw')` 解壓 zip 內的 `xl/workbook.xml`、`xl/_rels/workbook.xml.rels`、`xl/sharedStrings.xml`、`xl/worksheets/sheetN.xml`，再用 `DOMParser` 處理 XML。
- 備援格式：`.csv`（UTF-8），供無法解析 xlsx 時手動轉用。

## 資料處理管線

1. `FileReader` 讀取為 `ArrayBuffer`。
2. 解析中央目錄（End of Central Directory + 各 entry 的 local header）取得 `xl/` 內部檔案的壓縮資料與壓縮方式（`deflate`/`stored`）。
3. 以 `DecompressionStream('deflate-raw')` 解壓縮 `deflate` entry，`stored` 直接複製。
4. XML 解析，建立 workSheet 模型：
   - 依 `sharedStrings` 與 `<c t="s">` 對映文字。
   - 依欄位位置（excel col 字母 → index）對映至表頭。
   - **日期轉換**：上述里程碑日期欄與 `填單日期` 的 Excel 序列號（如 `46252`）以 1899-12-30 為起點轉成 `YYYY-MM-DD`（回推 1900 閏年 bug 不處理，視為可接受的 1 天誤差），並保留原始數值。
   - 過濾全空白列（僅有序號的樣板列）。
4b. **欄位語意（重要，來自使用者領域知識）**：
   - 欄位一律**以表頭名稱對應欄位**（不寫死欄位 index），避免欄位順序變動導致錯位。
   - 以下 6 個欄位是**里程碑日期欄**（Excel 日期序列號），「只要有填日期即代表那一天發生該里程碑」：
     `填單日期`、`初步接洽`、`需求確認`、`報價`、`簽約`、`導入`。
   - 呈報時逐層顯示漏斗：填單 → 初步接洽 → 需求確認 → 報價 → 簽約 → 導入。
   - `簽約` 與 `導入` 的填寫規則依 **`類別`** 欄位解讀（領域規則，來自使用者）：
     - `類別` = **零擔／甲配** → `簽約` **與** `導入` 都會有日期。
     - `類別` = **1P／3P** → **`簽約` 空白、`導入` 有日期**。
     - 驗證規則：若 `導入` 有日期但 `簽約` 空白 → 判定為 1P/3P；兩者都有 → 零擔／甲配。報表可用此規則做一致性檢查並以 `類別` 為維度交叉呈現。（資料中 `類別` 實際值：零擔、1P(SCM)、3P(MO+)；「甲配」暫未出現。）
   - `結案` 欄為結案原因說明文字，**用於判定案件是合作結案或不合作結案**，非日期、非里程碑。
   - **`洽談內容` 為重要分析欄位（來自使用者領域知識）**：free-text 逐次洽談紀錄（日期＋過程描述），作為**分析洽談詳細內容與過程**的核心來源：
     - 表格中**可展開完整內容**（展開列或 modal），不受單格截斷限制。
     - 納入**全文關鍵字搜尋**（與其他欄位一起）。
     - 依客戶列出**洽談過程時間線**（依內文日期標記），供個案分析。
5. 案件狀態分類（依 **`結案` 欄文字**判定，`結案` 內容是結案原因，用以區分合作／不合作結案）：
     - **合作結案**：`導入完成` → 合作成功
     - **不合作結案**：`婉拒` → 客戶婉拒；`三聯皆失敗` → 聯繫失敗；`考慮中` → 客戶考慮中／暫緩；`需求無法滿足` → 需求無法滿足（暫緩）
     - 其他含「結案」文字 → 其他結案（依文字歸類為合作或不合作）
     - `結案` 空白但 `洽談內容` 含進度 → 進行中
     - 全部空白 → 未啟動
     - `說明` 欄為額外備註，不作為狀態判定依據。
6. 統計：課別分布、案件狀態分布、開發者件數、服務類別（甲指/甲配/零擔/3P/1P）分布、導入完成清單等，全部即時由目前篩選結果重算。
   - **`開發者` = 業務代表姓名，用於開發排行（來自使用者領域知識）**。
   - 提供 **排行分析**：
     - **開發者排行**：依「案件總數／合作結案數／導入完成數／簽約數」計分排名（可切換指標，預設按案件數）。
     - **課別排行**：各課案件數、合作結案數。
     - **站所排行**：各收貨站所案件數、導入完成數。

## UI 版面

1. 標頭：標題 + 目前載入檔名 + 拖曳/選檔區。
2. 統計卡（頂、可點擊當作篩選）：總客戶數、合作結案數、不合作結案數、成案率、各課數。
2b. **里程碑漏斗**：填單 → 初步接洽 → 需求確認 → 報價 → 簽約 → 導入 各階段累計客戶數（依各日期欄有值統計），以及「簽約/導入／分類別（零擔 vs 甲配）」交叉表（`簽約`、`導入` 欄位配合 `類別` 欄位解讀）。
2c. **時程分析（天數）**：依里程碑日期欄計算各階段天數：
     - 分段：填單→初步接洽、初步接洽→需求確認、需求確認→報價、報價→簽約、簽約→導入。
     - 每階段呈現：樣本數、平均／中位數／最長／最短天數。
     - 總時程：`填單日期`→`導入` 的總天數（1P/3P 無 `簽約`，以填單→導入為準；零擔/甲配可額外給填單→簽約天數）。
     - 圖表：各階段平均天數長條圖 + 總時程分布（柱狀直方圖）。
     - 規則：僅當起點與終點均有日期才計入；同天算 0 天；異常（終點早於起點）排除並提示。
2c2. **進度追蹤表（交叉表＋每格進度條）**：以「類別」與「課別」兩個維度各一張交叉表（先類別、後課別）：
     - 列＝群組（類別：零擔→1P(SCM)→3P(MO+)→甲配，其餘依名稱；課別：北一→北二→北三→中→南一→南二→分轉部，其餘依名稱）；欄＝`填單日期→初步接洽→需求確認→報價→簽約→導入→合作結案`＋填單數合計。
     - 各里程碑計「該日期欄非空」筆數（與漏斗一致）；合作結案＝`classifyStatus==='合作成功'` 數。
     - 每格顯示計數＋迷你轉化長條（以該群組填單數為分母）；合作結案欄以綠色標示；末列為全體合計。
     - 表格右上角標記單位「客戶數」；與分析期間＋篩選同步縮放。
     - 註記：1P/3P 客戶「簽約」空白故簽約數偏低，「導入」多於「簽約」屬正常。
2d. **流失節點分析（drop-off）**：
     - 對未到 `導入`（非合作結案）的客戶，找出其**最後到達的里程碑節點**（填單／初步接洽／需求確認／報價／簽約／導入，取有日期的最後一階段）。
     - 依 `類別` 計算大多數客戶停在哪一個節點之後停止洽談（各節點停止人數 + 占比，以長條圖／熱表呈現）。
     - 點選某節點 → 列出該批客戶，並**取出 `結案` 原因與 `洽談內容`**（完整文字），供了解流失主因。
3. 篩選列：課別、案件狀態、開發者、服務類別下拉＋關鍵字搜尋＋重新整理。
4. 圖表區（原生 SVG）：課別長條圖、案件狀態圓餅／甜甜圈圖、**`類別` 數量占比圓餅圖**（零擔／1P(SCM)／3P(MO+) 各占比例）、**`類別` 導入成功率**（各類型導入完成數／該型總數，以長條或進度條呈現）、開發者績效橫條圖、時程分布圖。另有**排行表**：開發者／課別／站所排行（含案件數與合作/導入數，可切換指標排序）。無資料時顯示空狀態。
5. 明細表：25 欄可排序、簡易分頁（每頁 50），篩選後即時更新，並顯示「目前 N / 總 M 筆」。
5b. **洽談內容檢視**：點列 → 展開或 modal 顯示完整 `洽談內容`＋`說明`，並以文字時間線呈現洽談過程。
6. 匯出區：篩選結果 → CSV（Blob download，UTF-8 with BOM）；`window.print()` 列印 PDF。

## 錯誤處理

- 非 xlsx/csv 檔案 → 錯誤訊息提示。
- zip 結構缺必要檔案 / XML 損毀 → 顯示可讀錯誤。
- `DecompressionStream` 不支援（舊瀏覽器）→ 提示更新瀏覽器。
- 欄位缺值以空白呈現；統計卡下方顯示主要欄位填寫率。

## 驗證方式

- 用 `customer.xlsx` 實測：載入後統計卡、圖表、表格數字須與人工分析一致（97 筆有意義資料、導入完成 18、聯繫失敗 16、客戶婉拒 13 等）。
- 里程碑日期欄須正確轉成日期顯示；`簽約`/`導入` 統計須以 `類別`（零擔/甲配）交叉解讀。
- 時程分析：各階段平均天數與總時程（填單→導入）須與日期欄交叉驗證（如同日差 0、循序遞增）。
- 流失節點分析：未導入客戶的最後節點分布、依 `類別` 交叉，須能下鑽到該批客戶的 `結案` 原因與 `洽談內容`。
- 篩選／排序／匯出 CSV；`file://` 直接開啟可運作。
